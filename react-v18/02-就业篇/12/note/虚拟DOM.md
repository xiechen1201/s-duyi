# 虚拟DOM

什么是虚拟 DOM？

本质上就是一个普通的 JS 对象，用于描述视图的界面结构。

最早由 React 团队提出，解释称为是一种编程概念（只要能把 DOM 结构描述出来，无论什么方式，那么这就是一个虚拟 DOM）。

在 React 中使用的是 JS 对象来对 DOM 结构进行描述，导致很多人就把 JS 对象和虚拟 DOM 划等号。这种理解是不准确的。

虚拟 DOM 和 JS 对象的关系：前者是一种思想，后者是一种思想的具体实现。

## 为什么需要？

两个方面的优势：

1、比 DOM 体积优势和速度优势

2、对平台的渲染抽象能力

### 优势和速度优势？

需要明确 JS 层面计算要比 DOM 层面计算要快。

- DOM 对象要被浏览器渲染之前，浏览器会有很多的工作要处理（浏览器的渲染原理）；

- DOM 对象上的属性也非常多；

操作 JS 对象的时间和操作 DOM 对象的时间是完全不一样的（见代码片段）。JS 计算高于 DOM 计算。

虽然 JS 很快，但是依旧需要 DOM 对象来渲染视图。

虚拟 DOM 在第一次渲染的时候没有优势，比直接操作 DOM 要慢，真真的优势是在更新阶段。

### 平台抽象

UI = f(state) 

- 根据自变量计算出 UI

- 根据 UI 执行具体的宿主环境 API

虚拟 DOM 是对真实 UI 的描述，根据不同的宿主环境，执行不同的渲染代码。
