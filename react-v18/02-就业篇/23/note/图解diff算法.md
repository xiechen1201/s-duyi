# 图解diff算法

diff 算法的流程？为什么没有采用 Vue 的双端 diff 对比？

Render 阶段会生成 FiberTree，diff 就是发生在这个阶段。

这里的 diff 指的是 current FiberNode 和 JSX 对象（React 元素）之间进行对比，然后生成  workInProgress FiberNode。

> 其他使用虚拟 DOM 的前端框架也会有类似的流程。例如 Vue 将这里的流程称为 patch。

diff 算法本身是又性能上面消耗的，react 文档中提到即使使用最前沿的算法，如果要完整的对比两颗树，那么算法的复杂度都会达到 O(n^3)，n 表示元素的数量，如果 n 为 1000，要执行的计算量会达到十亿量级。

因此为了降低算法的复杂度，react 为 diff 算法设置了 3 个限制：

1. 只对同级别元素进行 diff，如果一个 dom 元素在前后两次更新中跨越了层级，那么 React 不会尝试复用。

2. 两个不同类型的元素会产生不同的树，例如元素从 div 变成了 p，那么 react 会直接销毁销毁 div 以及子孙，新建 p 以及 p 的子孙元素。

3. 开发者可以通过 key 来暗示哪些子元素在渲染下能够保持稳定。

对同层级元素进行 diff 如何进行 diff？

- 更新后只有一个元素，此时就会根据 newChild 创建对应的 wip FiberNode，对应的流程就是单节点 diff

- 更新后有多个元素，此时就会遍历 newChild，创建对应的 wip FiberNode，以及它的兄弟元素，此时对应的流程就是多节点 diff

## 单节点 diff

单节点指的是新节点为单一阶段，旧节点的数量是不一定的。

单节点 diff 是否能够复用遵循下面的流程：

- 判断 key 是否相同

  - 如果没有设置 key，那么 key 就是 null，也属于相同的情况

  - 如果 key 相同，进入到步骤二

  - 如果 key 不同，不需要进入步骤二，无需判断 type，结果直接为不能复用

- 如果 key 相同，再判断 type 是否相同

  - type 相同，复用

  - type 不同，不能复用

## 多节点 diff

所谓多节点 diff 指的是新节点有多个。

react 团队发现日常开发中对节点的更新操作往往高于对节点的新增、删除、移动，所以在进行多节点 diff 的时候，react 会进行两轮遍历。

- 第一轮会尝试逐个的复用节点；

- 第二轮遍历会处理上一轮遍历中没有处理完的节点；
